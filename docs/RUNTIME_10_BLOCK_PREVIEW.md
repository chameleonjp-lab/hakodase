# 通常プレイ10箱化

## 1. 目的

公開中の通常プレイを4箱の暫定盤面から10箱へ進める。

対象は次の2モードである。

```text
本日の出荷
daily

エンドレス
endless
```

練習モードは基本操作を確認するため、2箱のまま維持する。

## 2. 通常プレイの固定条件

```text
盤面: 7×9
箱: 10個
色: 4色
同色箱: 4個 / 2個 / 2個 / 2個
初期直行箱: 0個
厳密最短: 24操作
generatorVersion: route-catalog/3.0.0
runtimeBankVersion: runtime-b10c4-preview/1.0.0
```

盤面はP3-03Rで厳密検証した`b10c4`の12構造から選ぶ。

## 3. 公開ブラウザで行わない処理

公開ゲームの開始時には次を実行しない。

```text
厳密ソルバー
1001件監査
候補生成探索
人間試遊パック生成
```

公開ブラウザは、検証済みの経路カタログから次だけを行う。

1. seedから12構造の1件を選ぶ。
2. 左右反転、上下反転、180度回転のいずれかを選ぶ。
3. 4色の置換を決める。
4. 箱、壁、搬出口、一方通行床を組み立てる。

通常プレイの12構造には一方通行床を含まない。

## 4. 実装

```text
src/core/runtime-ten-block-bank.js
src/core/generator.js
src/app/modes.js
index.html
```

`runtime-ten-block-bank.js`は`generator-v3-catalog.js`だけを読み込み、`generator-v3-proof.js`と`exact-solver-v2.js`を公開プレイ経路から読み込まない。

## 5. 識別情報

通常プレイ結果へ次を持たせる。

```text
puzzleId
profileId: b10c4
templateId: b10c4-t00〜b10c4-t11
generatorVersion: route-catalog/3.0.0
source: runtime-b10c4-preview/1.0.0
```

正式問題集ではないため、`puzzleId`は`preview-`で始める。

## 6. モードごとの扱い

### 本日の出荷

- 固定seedを使用する。
- 10箱・4色・最短24操作。
- 厳格時計を維持する。
- 正式ランキングへ送らない。

### エンドレス

- seedから10箱盤面を選ぶ。
- 同じseedは同じ盤面を返す。
- 端末内記録を維持する。
- 公式総合ランキングへ送らない。

### 練習

- 2箱のまま維持する。
- 通常プレイの記録へ混ぜない。

## 7. 自動検査

Nodeテストで次を確認する。

- 構造数は12件。
- 全構造の箱数は10個。
- 全構造の色数は4色。
- 色別の箱数は`4 / 2 / 2 / 2`。
- 全構造の最短値は24操作。
- 全構造の初期直行箱は0個。
- 同じseedは同じ盤面を返す。
- 公開用盤面と開発用生成器v3が同じ盤面を組み立てる。
- 未登録テンプレートを推測生成しない。

ブラウザテストで次を確認する。

- 本日の出荷を開始すると10箱を持つ。
- 色数は4色。
- 目安は24操作。
- 残り表示は10箱から始まる。
- 320×568、390×844、1280×720で既存フローを壊さない。

## 8. 対象外

```text
P3-05の人間試遊完了
30問以上の正式問題集
正式puzzleId
Supabase公式ランキング
出荷シャッター
通常プレイへの一方通行床追加
```

今回の10箱化は、ゲームとしての密度を上げる公開試作である。公式問題への昇格は、P3-05の人間試遊を通過した後に別工程で行う。
