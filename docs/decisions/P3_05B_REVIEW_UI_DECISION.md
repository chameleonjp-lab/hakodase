# P3-05B 試遊レビュー画面の決定

日付: 2026年7月28日

## 決定

1. P3-05Aの66候補を、iPhoneから順番に遊べる専用`review.html`を追加する。
2. 通常ゲームのホームにはレビュー画面へのリンクを置かない。
3. `review.html`へ`noindex,nofollow`を指定する。
4. 候補は`docs/review/P3_05_REVIEW_PACK.json`から読み、画面上で再生成しない。
5. 固定盤面を既存の`GameEngine`、`CanvasRenderer`、`PointerInput`で遊ぶ。
6. レビュー画面では厳密ソルバー、候補生成、1001件監査、ランキング送信を実行しない。
7. 候補切替、profile絞り込み、前後移動、次の未評価への移動を用意する。
8. 試行回数は「試遊開始」または「やりなおす」を押した時に増やす。
9. クリア数、ベストタイム、ベスト操作数はゲーム結果から自動記録する。
10. 面白さ、分かりやすさ、難しさ、他候補との違い、失敗への納得感を各1〜5で記録する。
11. 判断は`pending / accept / revise / reject`の4種類とする。
12. P3-05Aの記録検証契約を変更しない。
13. 試遊記録は端末の`localStorage`へ保存する。
14. 候補記録と試遊者情報は別の保存キーを使う。
15. packVersionや候補識別子が一致しない記録は自動復元しない。
16. 記録JSONはWeb Share、クリップボード、テキスト表示の順で書き出す。
17. JSON取込時は版、未知候補、重複候補、候補識別子、記録値を検査する。
18. Codeberg Pagesでは`review.html`と候補パックJSONだけを追加公開する。
19. 空の試遊記録JSONやCSVはCodebergへ公開しない。
20. `accept`が30件以上になっても、レビュー画面だけで公式問題集を自動確定しない。

## 理由

- ユーザーの開発環境はiPhone中心であり、CSVを手作業で編集するより、実際の盤面と評価フォームを同じ画面へ置く方が誤りを減らせる。
- 候補生成や厳密探索をiPhoneで実行すると、起動時間と電池消費が増え、固定候補を評価する目的から外れる。
- 端末内保存だけでは端末故障やブラウザ消去で失われるため、JSON共有を必須の退避手段として用意する。
- 一般プレイヤー向けゲームと試遊レビューを分けることで、未採用候補や評価項目を通常体験へ混ぜない。

## 禁止事項

- reviewIdだけを信用して異なるboardHashの記録を読み込まない。
- 未クリア候補を`accept`完了として数えない。
- 人間記録が厳密最短を下回った状態を無視しない。
- review画面からSupabaseへ送信しない。
- 代表解法を自動操作して人間試遊済みと扱わない。
- 端末内保存の成功を確認せず保存済みと表示しない。
- review画面の進捗だけで正式問題IDを発行しない。
