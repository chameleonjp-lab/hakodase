# P3-04 品質指標・大量監査の決定

日付: 2026-07-27

## 決定

1. P3-03候補を、厳密最短20〜35操作だけで公式問題候補へ進めない。
2. 1000件以上の条件は1001件の決定論的監査として実施する。
3. 監査seedは`p3-04-audit-v1-<index>-<profile>`形式とし、7profileを順番に選ぶ。
4. 各候補はP3-03生成器を通常どおり実行し、P3-02の厳密解と解法再生を毎回通す。
5. `boardHash`重複と、色・ID・反転を除いた`structureHash`重複を分けて数える。
6. 初期直行箱が1件以上ある候補はhard rejectとする。
7. 初期分岐、判断手率、壁利用率、同箱反復、方向偏り、色偏りは暫定review flagとし、監査結果を読む前にhard rejectへしない。
8. 誤手・詰み指標は、代表解法の各状態から代表手以外を1手だけ適用し、直後に合法手0件となる割合とする。
9. 8の指標を完全な詰み率と呼ばず、`即時詰み代替率`とする。
10. 大量監査は通常のNode・Browser Gateから分離し、専用GitHub Actions jobで実行する。
11. 大量監査jobはrejectやreviewの多さでは失敗させない。1001件を正しく処理し、証拠を保存できたかを処理成功条件とする。
12. 監査artifactだけに依存せず、結果summaryを同じPull Requestへ文書として固定する。
13. P3-04結果が構造上の不足を示す場合、P3-05へ進まずP3-03Rとして生成器を補修する。
14. P3-04とP3-05を通るまで、P3-03候補をCodeberg公開版へ接続しない。

## hard reject

```text
no-initial-legal-action
initial-direct-exit
```

## 暫定review flag

```text
low-initial-branching
low-decision-density
low-wall-utilization
high-same-block-repeat
high-direction-bias
high-color-bias
```

## 暫定閾値

```text
初期合法操作: 2件以上
判断手率: 25%以上
壁利用率: 5%以上
同箱連続率: 55%以下
最大方向偏り: 70%以下
最大色偏り: 70%以下
```

## 判断理由

- 最短操作数が長くても、一本道、同じ箱の反復、直行退場、未使用の壁で水増しできる。
- `boardHash`だけでは色置換と反転を別問題として数えるため、構造の種類を過大評価する。
- 誤手の将来可解性を全分岐で厳密探索すると、1001件監査の処理量が大きくなる。最初は1手先の即時詰みを安定して計測し、必要なら後続で深い検査を追加する。
- 自動数値は面白さの代理であり、人間試遊を置き換えない。
- 監査結果そのものが悪くても、それを隠さず再現可能な証拠として残すことがP3-04の目的である。

## 対象外

- 全最短解法数の列挙。
- 全誤手についてクリア可能性を最後まで探索する処理。
- 人間試遊。
- 公式問題IDの発行。
- 公開ゲームへの接続。
- Supabaseランキング。
