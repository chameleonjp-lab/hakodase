# P3-03 生成器v2 判断記録

- 日付: 2026-07-24
- 対象: HAKODASE Phase 3
- 状態: proposed / Pull Requestレビュー待ち

## 決定

1. P3-03の候補生成は、完全な自由ランダム配置ではなく、壁で分離した経路scaffoldをseedで変換する方式とする。
2. `generatorVersion`は`route-scaffold/2.0.0`とする。
3. 箱数8〜14を1箱刻みで覆う7profileを用意し、色数3〜6と同色複数箱を含める。
4. seedからprofile選択、同型経路間の箱数配分、左右・上下・180度変換、色置換を決定する。
5. 候補はP3-02厳密ソルバーで再計算し、厳密最短20〜35操作の時だけ返す。
6. 解法列を再生できない候補、ソルバー上限で証明できない候補、`official` profileに通らない候補は返さない。
7. `puzzleId`は候補段階ではprofileと`boardHash`から作り、正式採用時はP3-05で運用用IDを発行する。
8. 公開ゲーム開始時には生成器も厳密ソルバーも実行しない。事前生成問題集だけを読み込む。
9. 14箱・3色など、検証profileへ存在しない組合せを推測で生成しない。
10. P3-03の候補を最短操作数だけで公式問題へ昇格させない。

## 理由

旧MVPの完全ランダムに近い壁配置は、箱を出口と一直線へ置く可解性保証と結び付き、4箱4操作の構造的な破綻を作った。

自由配置を大量に厳密探索すると、解なし候補や探索上限候補が増え、生成時間と再現性が不安定になる。

経路scaffold方式では、候補の可解性と探索規模を制御しつつ、seedによる変換と色置換を行える。ただし構造の種類が限られるため、P3-04で重複と品質を測り、P3-05で人が判断する必要がある。

## 代替案と見送り理由

### 実行時の完全ランダム生成

- 厳密ソルバーが端末起動を止める。
- 上限到達候補を誤って採用する危険がある。
- 同じ競技条件を保証しにくい。

### 推定難易度だけで20〜35操作とみなす

- 旧MVPと同じく、距離と操作数を混同する危険がある。
- 正式契約に反するため採用しない。

### 試作盤面バンクをそのまま増やす

- 4箱・8〜12操作の暫定構造から抜けられない。
- 8〜14箱、同色複数箱、20〜35操作を満たさない。

### P3-03で品質指標と1000件検査まで同時実装

- 生成規則の不具合と品質判定の不具合を分離できない。
- 1目的1Pull Requestの方針に従いP3-04へ分ける。

## 既知の制限

- 構造は経路scaffold群に限定される。
- 色置換や全体反転だけでは、別のパズル構造にならない場合がある。
- 14箱profileには初期直行箱が含まれうる。
- 分岐、壁利用、誤手、詰み、反復、偏りはまだ採否へ使わない。
- 人間試遊は未実施。

## 次の判断

P3-04で1000件以上を検査し、次を確定する。

- profile別の採用率。
- `boardHash`重複率。
- 初手分岐の許容範囲。
- 直行可能箱数の上限。
- 壁利用率の下限。
- 誤手・詰み指標の許容範囲。
- 生成器profileの追加、修正、廃止。
