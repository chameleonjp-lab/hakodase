## 5. BLOCKER 1: 初期直行箱

hard reject理由は次の1種類だけだった。

```text
initial-direct-exit: 572件
```

profileごとの症状:

```text
b09c3: 全143件で初期直行箱1個
b11c4: 全143件で初期直行箱1個
b13c5: 全143件で初期直行箱1個
b14c6: 全143件で初期直行箱2個
```

偶発的なseed不良ではない。各profileのscaffoldと箱数配分が、初期直行を必ず作る構造になっている。

P3-03Rでは、全profile・全候補について次を満たす必要がある。

```text
initialDirectExitBlockCount = 0
```

初期直行を含む候補を生成後に捨てるだけではなく、経路形状と初期配置を直し、十分な採用率を維持する。

## 6. BLOCKER 2: 構造の種類不足

1001件の`boardHash`は656種類だった。しかし、色番号、箱ID、左右・上下反転、180度回転を正規化した`structureHash`は27種類だけだった。

さらに、hard ruleを通過した429件に限定すると次の結果だった。

```text
一意boardHash: 217
一意structureHash: 3
```

通過したprofileは次の3種だけで、それぞれ構造は1種類だった。

```text
b08c3: 143件 → 1構造
b10c4: 143件 → 1構造
b12c5: 143件 → 1構造
```

つまり、色置換、反転、箱ID差によって`boardHash`は増えているが、遊び方の基礎構造はほぼ増えていない。

P3-05では30問以上を目標にしているため、3構造から30問を作ることは認めない。

## 7. その他の品質指標

### 判断手率

平均90.85%で、代表最短解法中に複数の合法操作がある場面は多い。

ただし、合法手が複数あることだけでは、それらが意味のある選択肢であるとは限らない。構造の種類不足を補う証拠にはならない。

### 壁利用率

平均16.77%だった。

代表解法で使われた壁は存在するが、多数の壁は経路外を埋めるための壁である。現在のscaffold方式では、壁数をそのままパズルの複雑さとして評価できない。

### 即時詰み代替率

全1001件で0%だった。

これは次のどちらかを意味する可能性がある。

- 1手の誤りでは即座に詰まず、回復可能な候補である。
- 誤手の影響が数手後に現れるため、1手先検査では検出できない。

P3-04の指標は1手先だけを見るため、完全な詰みが存在しないとは判断しない。

### 反復・方向・色偏り

暫定review閾値を超える候補はなかった。

```text
同箱連続率 平均: 35.78%
最大方向偏り 平均: 38.85%
最大色偏り 平均: 45.52%
```

この結果は、現在の代表解法が閾値内にあることだけを示す。構造同型の多さは別のBLOCKERとして扱う。

## 8. P3-03Rの必須補修

P3-03Rでは、次を実装する。

1. `b09c3`、`b11c4`、`b13c5`、`b14c6`の初期直行箱を0件にする。
2. 単一scaffoldの反転・色置換だけに依存せず、複数の独立した経路構造を用意する。
3. profileごとに複数の壁配置・経路接続・箱依存関係を持たせる。
4. 厳密最短20〜35操作とP3-02解法再生を維持する。
5. 生成失敗時に未検証フォールバックを返さない。
6. 同じseedの決定性を維持する。
7. P3-04監査を同じseed prefixで再実行し、旧版との比較表を残す。

P3-03Rの暫定受け入れ条件:

```text
1001件生成完走
生成失敗0を目標
全profileで初期直行箱0
hard reject 0を目標
hard rule通過候補の一意structureHash 60件以上
各profileで一意structureHash 5件以上
厳密最短20〜35操作を全件維持
```

`60件以上`は、P3-05で30問以上を人間試遊・選別するため、最低2倍の構造候補を確保する暫定条件である。監査結果を踏まえ、緩和する場合はDecision Logへ理由を残す。
