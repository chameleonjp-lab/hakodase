# ChatGPT向け申し送り — HAKODASEのリプレイ性評価

## このフォルダの目的

このフォルダは、HAKODASEを「何度も挑戦して遊ばれる短時間パズル」へ改善するために実施した、実プレイ・コード確認・問題生成測定の成果を引き継ぐためのパッケージである。**ゲーム本体の仕様や実装を変更するPRではなく、次の実装担当が判断と作業を再現できるようにする分析資料PR**である。

評価対象は commit `c031eb089b9291880ff2e958e38c3f1e9a79de48` であり、評価日は2026-08-16である。元の評価レポートは本フォルダ内に固定コピーしているため、以降の改修でルートの作業ファイルが変化しても、評価根拠を参照できる。

## 引き継ぐべき結論

HAKODASEは、ドラッグ操作、色と記号を併記した箱・出口の識別、退場アニメーションという基本体験が良い。一方、**リプレイ性の加重評価は3.75 / 10**であり、繰り返し挑戦を支える「公正なスコア」「戦略的に深い問題」「失敗からの回復」「クリア後の次行動」が未完成である。

| 優先度 | 確認済みの問題 | 影響 | 最初に取るべき対応 |
|---|---|---|---|
| P0 | タイマーが盤面表示直後から進み、初手前の時間まで記録される。 | 自己ベスト・ランキングの公平性が成立しない。 | 練習・エンドレスでは最初の有効操作、公式競技ではGOと同時に開始する。 |
| P0 | 達人の最短目標がHUDで`—`になる。 | 高難易度の目標と達成感が消える。 | 事前検証済みの問題カタログを用い、未算出問題を採用しない。 |
| P1 | 200問測定で最短操作数は練習2、初級3、標準4操作に固定された。 | 箱数は増えても、熟達を要する戦略深度が増えない。 | 20〜35操作で、停止位置作り・順序判断・回復を含む問題へ移行する。 |
| P1 | 上級の36/200問、達人の200/200問で生成時ソルバーが`-1`を返す。 | `exact: true`と最短目標の表示が矛盾する。 | 公開時に探索を走らせず、開発時に十分な上限で最短解を固定する。 |
| P1 | Undo APIはコアにあるが画面上で使えず、詰み・無効手の支援も薄い。 | 誤操作が離脱になりやすい。 | Undo、詰み通知、無効手のフィードバック、結果画面を実装する。 |

## 次の実装担当への指示

最初の実装PRは、機能を広げずに**P0の計時と最短目標の信頼性**を直すことを推奨する。Three.js化、オンラインランキング、過剰な演出の追加は後回しにする。見た目を改善しても、問題構造とスコアが信頼できなければ再挑戦の動機は生まれない。

P0の完了後、P1として検証済み問題カタログと画面状態を整備する。モードは、概念を教える固定問題の「練習」、同一問題を競う「本日の出荷」、seedで発見を楽しむ「エンドレス」に分ける。公式問題は実行時のランダム生成物を使わず、`puzzleId`、`rulesVersion`、`generatorVersion`、`boardHash`、最短解を持つ事前検証済みデータから選ぶ。

## 再現手順

リポジトリのルートから以下を実行する。評価はNode標準機能のみで再現できる。

```bash
npm test
node docs/chatgpt-handover/2026-08-16-replayability-evaluation/evidence/run-generation-evaluation.mjs
node docs/chatgpt-handover/2026-08-16-replayability-evaluation/evidence/run-solver-limit-probe.mjs
```

生成分布の期待値は、練習が2操作、初級が3操作、標準が4操作へそれぞれ200/200問で収束すること、上級・達人では20,000ノード上限により最短操作数が未算出になる問題が現れることである。ソルバー上限を上げた再検証では、抽出した未算出問題が可解であり、本来は上級5操作・達人6操作であることを確認できる。
