# HAKODASE 問題生成バランス設計案

**目的:** 日替わり要素に頼らず、毎回異なる盤面でも「一度解く」から「もっと良い順序を見つける」「別解を試す」へ自然に移れる問題生成を実現する。
**前提:** 本書は現行のCanvas版、スライド移動、色＋記号の搬出口、seed再現性を残す。[1] [2]

## 結論

現在の問題生成は、各箱を対応する出口と同一直線上へ置き、後から置いた箱から出す逆生成で可解性を保証している。[1] この方式は堅牢だが、**最短解が「箱の数だけ、各箱を一度出す」解へ収束する**。実測でも練習から標準まで最短2・3・4操作に固定され、上級・達人も本来はほぼ5・6操作である。[3]

リピートプレイ率を高めるには、壁の数や色数だけを増やしてはいけない。生成の目的関数を、旧来の「移動距離が長い」から、次の4点へ置き換える必要がある。

> **最適解に十分な操作数があり、セットアップ操作に意味があり、少数の誤りから立て直せ、同じ手順に見える問題が連続しないこと。**

まずは「完全ランダム生成を毎回プレイヤーへ出す」方針を採用せず、開発時またはバックグラウンドで生成・検証した**問題プール**からランダムに選ぶ。日替わりは不要である。プレイヤーには毎回ランダムな一問として見せ、同じseedは再挑戦・共有用にだけ使う。この設計なら品質を担保しつつ、問題の新鮮さを維持できる。

## 1. 生成器を変えるべき理由

### 現行方式の長所と限界

現行の`buildSolvableBoard`は、出口から盤内へ入るセル列を選び、箱を出口と一直線の位置へ置く。可解性を素早く保証でき、フォールバックも安定している。[1] しかし、この「出口から逆向きに箱を一度だけ入れる」構造では、箱を別の位置へ動かして止める操作、別箱のための停止点を作る操作、出口への経路を段階的に開ける操作が生まれにくい。

| 現行の評価軸 | 起きること | リピート性への影響 |
|---|---|---|
| 移動距離の下限 | 一度の長いスライドで距離だけが増える。 | 思考量よりアニメーション時間が増えやすい。 |
| 色数＝箱数 | 難易度が箱数にほぼ比例する。 | 「同じ問題の箱数違い」に見えやすい。 |
| 直接退場可能な配置 | どの箱も出口方向へ一度滑らせればよい。 | 解法の発見より、出口と箱の対応確認になりやすい。 |
| 可解性だけの採用 | 解けるが、分岐・回復性・新規性は保証しない。 | 初見の面白さと再挑戦の余地にばらつきが出る。 |

v2契約が定める「最短操作数20〜35」「直接搬出だけで終わらない」「正しい順番を複数回考える」という基準は、この限界を正しく捉えている。[4] 今後は、移動距離ではなく`optimalSwipes`、非退場操作、順序依存、回復可能性を採用条件にする。

## 2. 目指す問題の手触り

良い問題は、初見で「何を動かせばよいか」が完全には分からず、しかし不条理には感じない。プレイヤーが1〜3手試すと、出口への経路や停止位置の意味が見え、クリア後には「次は無駄な1手を省けそうだ」と考えられる状態が理想である。

| 要素 | 目標となる体験 | 生成上の条件 |
|---|---|---|
| セットアップ | 箱を出す前に、別の箱または自箱の位置を整える。 | 最短解のうち非退場スライドを一定数含める。 |
| 順序依存 | 先に出す／動かすべき対象に理由がある。 | 少なくとも2〜4個の依存関係を持たせる。 |
| 選択 | 初手候補が少し複数ある。 | 合法手が1つだけ、または多すぎる状態を避ける。 |
| 回復 | 一部の試行錯誤から戻れる。 | 初期〜中盤の合法手の多くが解なしへ直行しない。 |
| 最適化 | クリアできても、より短い操作数や時間を詰められる。 | 最短解以外の可解解を持ち、差が1〜5操作程度ある。 |
| 新規性 | 次の問題が前問の焼き直しに感じない。 | 解法の型・出口側・壁トポロジーを連続させない。 |

### 避けるべき「難しさ」

難しいだけで気持ちよくない問題は、リピート率を下げる。具体的には、最初から合法手が1つしかない問題、1回の誤操作で不可逆な詰みになる問題、同じ見た目の壁が大量にある問題、色数だけを増やして視認負荷を上げた問題を除外する。特に、プレイヤーが失敗理由を盤面から読み取れない問題は採用しない。

## 3. 生成アルゴリズムの提案

### 方針: 「出口から箱を置く」から「解法を先に作って巻き戻す」へ

新しい生成器は、最初に隠れた解法列を作り、その解法を逆再生して初期盤面を得る。逆再生の途中に、**退場以外のスライド**を意図的に混ぜる。これにより、可解性を保ったまま、最短解にセットアップ操作を埋め込める。

```text
1. 盤面トポロジー、出口、色、箱数、解法の型を選ぶ。
2. クリア済み状態から、箱を出口経由で盤内へ再配置する。
3. 現在の状態に対して「この位置からこの方向へ滑らせると現在位置で止まる」逆スライドを複数回適用する。
4. 逆操作列を反転して、候補問題と隠れた解法を得る。
5. 独立ソルバーで最短操作数・解法・分岐・回復性を検証する。
6. 採用基準を満たした候補だけを問題プールへ保存する。
```

逆スライドは数学的に複雑に見えるが、実装では候補となる開始セルを列挙し、既存の`applySlide`を適用して「指定した終点に着地するか」を確認すればよい。すなわち、ルール実装を二重に持たず、現在の移動判定を正本として利用できる。[5]

### 基本生成フロー

| 段階 | 処理 | 実装上の要点 |
|---|---|---|
| A. 型の選択 | 後述する問題アーキタイプを選ぶ。 | 直近の出題と同じ型を避ける。 |
| B. 盤面骨格 | 壁、出口、出荷レーンなどを配置する。 | 壁は装飾でなく停止点・分岐点として使う。 |
| C. 解法の逆生成 | 退場操作と非退場操作を混ぜて初期状態へ戻す。 | 逆操作ごとに正方向の再生可能性を検証する。 |
| D. 正解検証 | 十分な探索上限で最短解を求める。 | 実行時ではなく事前生成時に高コスト探索を行う。 |
| E. 品質採点 | 深さ、回復性、分岐、新規性、可読性を点数化する。 | 閾値未満は棄却する。 |
| F. 問題プール化 | 問題本体、最短解、ヒント、特徴量を保存する。 | `puzzleId`、`boardHash`、`rulesVersion`を必ず持たせる。 |

### 逆生成だけで足りない場合の補助策

逆生成では、意図的に複雑な依存関係を作りにくい場合がある。その際は、**候補生成＋探索採用**を併用する。まず壁・箱・出口をランダムに配置し、ソルバーが解いた候補だけを採用する。ただし、可解なら採用ではなく、後述の品質フィルタをすべて通したものだけをプールへ入れる。

探索の上限を20,000ノードのままにしてはいけない。上級・達人で最短操作数が`-1`になる事実が確認されているため、オフラインの問題生成では100,000〜400,000ノード以上、またはA*・双方向探索・ヒューリスティック導入を前提にする。[3] プレイ中にこの探索を走らせないことが重要である。

## 4. 生成すべき問題アーキタイプ

問題プールに型を持たせることで、プレイヤーは「毎回違う考え方」を使う。初期段階では3〜4種類で十分であり、全ギミックを一度に入れない。

| 型 | 中心となる問い | 生成方法 | リピート性への寄与 |
|---|---|---|---|
| 停止点リレー | どの箱を壁・別箱の手前へ置けば次の箱が止まれるか。 | 2箱以上が同じレーンを使い、先行箱が停止点になる形を作る。 | 「出す」より「置く」思考を生む。 |
| 通路開通 | どの順序で通路を空ければ出口へ届くか。 | 出口直線上に別箱・壁の迂回路を置く。 | 順序の意味が視覚的に理解しやすい。 |
| 二段階搬出 | 箱をいったん別の辺・レーンへ寄せてから出す。 | 初期位置を出口と非一直線にし、曲がり角の停止点を用意する。 | 1箱あたり複数手を自然に作れる。 |
| 相互ブロック | Aを動かすとBが動かせ、Bを動かすとCが出せる。 | 2〜4個の依存グラフを作る。 | 解法の連鎖と「気付き」を作る。 |
| 同色ペア | 同じ出口を共有する2箱を、順番を考えて出す。 | 色数より箱数を多くし、同色箱を2個まで許可する。 | 色数を増やさずに密度と順序を増やす。 |
| レーン切替 | 一方通行の出荷レーンをどのタイミングで使うか。 | 既存の`oneway`ルールを少数だけ用いる。 | 上級以降に新しい論理を追加できる。 |

最初に実装するなら、**停止点リレー、通路開通、二段階搬出**の3種類だけでよい。出荷シャッターや一方通行床は、基本問題の操作数・回復性が安定してから追加する。ギミック追加は深さの代替ではなく、学習済みプレイヤーに新しい推論を渡すために使う。

## 5. 採用フィルタの具体値

以下の数値は初期の設計仮説であり、15人以上のプレイテストで更新する。重要なのは、単一の数値ではなく、複数の条件を同時に満たすことだ。

### 難易度別の目標値

| 項目 | 入門 | 標準 | 挑戦 | 熟達 |
|---|---:|---:|---:|---:|
| 盤面 | 5×6 または 6×8 | 7×9 | 7×9 | 7×9 |
| 箱数 | 3〜4 | 4〜6 | 5〜7 | 6〜8 |
| 色数 | 2〜3 | 3〜4 | 3〜5 | 4〜6 |
| 最短操作数 | 6〜10 | 12〜18 | 20〜28 | 25〜35 |
| 非退場操作の割合 | 30%以上 | 45%以上 | 55%以上 | 60%以上 |
| 初期状態で直接退場できる箱 | 1個以下 | 1個以下 | 0〜1個 | 0個 |
| 依存関係の数 | 1〜2 | 2〜4 | 4〜6 | 5〜8 |
| 最短との差がある可解解 | 1〜2操作 | 1〜3操作 | 2〜5操作 | 2〜6操作 |
| 目標初回クリア率 | 75〜90% | 45〜70% | 25〜50% | 15〜35% |

> **調整原則:** 入門は「理解できた」を作る。標準は「少し試せば解ける」を作る。挑戦と熟達は「クリア後に最短を詰めたくなる」を作る。全難易度で、理不尽な初見殺しは作らない。

### 採用・棄却の必須ルール

| 観点 | 採用条件 | 棄却条件 |
|---|---|---|
| 可解性 | 高い探索上限で最短解を確定できる。 | 最短解が未算出、または探索上限に到達する。 |
| 深さ | 上表の最短操作数と非退場比率を満たす。 | すべての箱を直接退場するだけで終わる。 |
| 初手 | 入門は1〜3、標準以降は2〜5個程度の意味ある合法手がある。 | 初手が1つだけ、または無意味な合法手だらけ。 |
| 回復性 | 初期〜中盤の主要な誤操作後も、Undoまたは数手の遠回りで解ける。 | 一見自然な1手で不可逆な詰みへ入る。 |
| 可読性 | 各壁・レーン・出口に明確な役割がある。 | 解法と無関係な壁が多く、盤面の意味が読めない。 |
| 新規性 | 最近出た問題と、解法型・出口辺・壁形状・色配置が異なる。 | 直近数問と同じ操作パターンを繰り返す。 |

## 6. 回復性を数値で判定する方法

リトライ率を高めるには、失敗を「やめどき」ではなく「学習」に変える必要がある。全ての誤操作を許す必要はないが、初見で自然に試しそうな手が即詰みになる問題は避ける。

### 回復性のオフライン検査

最短解の各状態で、最短解以外の合法手を列挙する。各手の後にソルバーを走らせ、以下へ分類する。

| 分類 | 定義 | 目標 |
|---|---|---|
| 最適継続 | その手でも最短手数を維持できる。 | 標準以降で一定数あると探索が楽しい。 |
| 軽い遠回り | 最短＋1〜5操作で解ける。 | 初期〜中盤の非最適手の過半をここへ寄せる。 |
| 要Undo | 解けるが大きく遠回り、または理解しにくい。 | 少数にとどめ、Undoで即回復できるようにする。 |
| 詰み | どの手順でもクリアできない。 | 入門では原則0、標準以降も自然な手では極小化する。 |

「自然な手」は、選択した箱を出口方向、見える空き通路方向、または直前に動かした箱と同じレーン方向へ滑らせる手として近似できる。これらの自然な手に詰みが多い候補は棄却する。完全な詰み判定をプレイ中に行う必要はないが、候補採用時には高コストでも検査する価値がある。

## 7. 多様性を保証する問題プール設計

日替わりがなくても、同じセッション内で「また同じ考え方だ」と感じさせないことはできる。生成候補へ特徴量を付け、出題時に直近履歴と比較する。

| 特徴量 | 例 | 重複回避の使い方 |
|---|---|---|
| 解法型 | 停止点リレー、通路開通、二段階搬出 | 同じ型を連続出題しない。 |
| 操作パターン | `R,U,L,exit`のような方向列 | 方向n-gramの類似度が高い候補を避ける。 |
| 出口分布 | 上辺中心、左右分散、下辺寄り | 同じ出口辺の構成を続けない。 |
| 壁トポロジー | 中央柱、分割通路、角のポケット | 見た目のシルエットを連続させない。 |
| 依存グラフ | 鎖型、分岐型、合流型 | 同じ順序読みを続けない。 |
| 色・記号配置 | 同色ペアの有無、出現順 | 色数が同じでも役割を変える。 |

プレイ中の選出は「完全なランダム」ではなく、候補プールから直近3〜5問と類似しないものを重み付き抽選する。seedを保存すれば、気に入った問題の再挑戦も再現できる。

## 8. 実装順序

### ステップ1: 測る値を正す

まず`shortestDistanceCells`を難易度・ランキングの主条件から外し、`optimalSwipes`を正本にする。現行では高難易度で探索上限により`-1`を返しつつ`exact: true`としているため、この不整合を解消する。[1] 問題データには、検証時の探索上限、最短操作数、最短解、生成バージョンを保存する。

### ステップ2: 1アーキタイプだけ作る

最初は「二段階搬出」だけを生成できるようにする。目標は標準問題で、4〜5箱、最短12〜18操作、非退場操作45%以上、初期直接退場1箱以下である。これが安定する前に、シャッターや一方通行を混ぜない。

### ステップ3: オフライン品質フィルタを追加する

候補盤面を生成し、最短解、初手分岐、非退場比率、回復性、重複度を測ってJSONへ出力するCLIを作る。閾値を満たす問題だけを`puzzles/`へ保存する。ブラウザの実行時は保存済み問題を読み、探索しない。

### ステップ4: 型を3種類へ増やし、問題プールを育てる

停止点リレー、通路開通、二段階搬出を各15〜20問ずつ作る。問題数を先に増やすのではなく、プレイテストで「似ている」「詰んだ理由が分からない」と言われた型を修正する。十分に安定した後に、同色ペアと一方通行レーンを追加する。

## 9. 最小実装仕様

最初の生成改修で追加すべきデータは次で十分である。

```js
{
  puzzleId: 'std-two-stage-001',
  rulesVersion: 2,
  generatorVersion: 'reverse-v1',
  boardHash: '...',
  board: { /* 現行の board 形式 */ },
  optimalSwipes: 14,
  optimalSolution: [
    { blockIndex: 2, dir: 'left' },
    { blockIndex: 0, dir: 'up' }
  ],
  metrics: {
    nonExitMoves: 7,
    directExitsAtStart: 1,
    dependencyEdges: 3,
    naturalDeadEndRate: 0.08,
    archetype: 'two-stage-exit'
  },
  hints: [
    '先に出口へ出せない箱を探そう。',
    '青箱が止まる場所を作る必要があります。',
    'まず緑箱を左へ動かしてみよう。'
  ]
}
```

このデータ形なら、問題生成・検証・実行時表示・ヒント・後の結果画面を分離できる。現行の`GameEngine`と`solveOptimalSwipes`は再利用し、`generator.js`だけに品質判断を詰め込まない方が保守しやすい。[5]

## 10. 最初のプレイテストで確認すること

問題生成の良し悪しは、ソルバーの数字だけでは判断できない。最低15人程度に、入門・標準・挑戦を各数問遊んでもらい、次を記録する。

| 観察項目 | 良い兆候 | 悪い兆候 | 調整先 |
|---|---|---|---|
| 初回の反応 | 盤面を見て自分から1手試す。 | どの箱を触るか分からず停止する。 | 初手分岐、視覚導線、入門問題。 |
| 失敗後 | Undoまたは再挑戦して別の手順を試す。 | 1回の失敗で終了する。 | 回復性、Undo、詰み率。 |
| クリア後 | 「もう少し短くできそう」と言う。 | 「終わった」で次へ移る。 | 最短との差、セットアップ量、結果表示。 |
| 問題間の印象 | 型の違いを感じる。 | 「さっきと同じ」と言う。 | 多様性フィルタ、アーキタイプ比率。 |
| 難易度感 | 難しい理由を説明できる。 | 理由が分からないまま難しい。 | 壁の役割、依存の可視性、自然詰み率。 |

## 最終提案

生成の成功基準を「常に解ける」から、**「解ける、考える、戻れる、もう一度詰めたくなる」**へ変える。最も効果が大きい順序は、以下である。

1. `optimalSwipes`を正しい難易度指標にし、探索結果が未算出の問題を排除する。
2. 二段階搬出を含む逆生成へ移行し、標準を12〜18操作まで深くする。
3. 非退場操作、順序依存、回復性、重複度を採用フィルタにする。
4. 検証済み問題プールから、直近の型に似ない問題をランダム選出する。
5. 停止点リレー、通路開通、同色ペア、レーン切替の順に型を増やす。

この順序なら、日替わりや外部ランキングを追加しなくても、各プレイヤーが「この盤面をもう一回、より少ない操作で解きたい」「次の問題はどんな型だろう」と感じる基礎を作れる。
